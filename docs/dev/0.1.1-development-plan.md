# 0.1.1 Development Plan

`0.1.1` is a patch hardening release for the `0.1.0` public API. It should
make implemented behavior easier to trust without expanding the crate into the
larger `0.2` feature set.

The release should stay compatible with the current workspace shape:

- Workspace version: `0.1.0` before the release bump.
- MSRV: Rust `1.95`.
- Selected SSH dependency: `russh 0.60.2`.
- Default features: `client`, `known-hosts`, and `aws-lc-rs`.
- Implemented runtime areas: client, server, known-hosts, shell, subsystem,
  SFTP client/server handler, TCP forwarding, StreamLocal forwarding, X11,
  agent forwarding, OpenSSH certificate auth, auth banners, and streaming exec.

## Release Goal

Ship a conservative follow-up release that:

- fixes documentation drift left after the `0.1.0` release candidate;
- adds runtime coverage for implemented but under-tested forwarding paths;
- hardens known-hosts, SFTP, and tunnel edge cases without changing the
  security model;
- keeps feature flags and MSRV stable;
- records an audit before publishing.

This release should not make broad public API changes unless a bug fix requires
one. Any incompatible change must be explicitly called out in `CHANGELOG.md`
and justified as pre-1.0 cleanup.

## Priority 0: Release and Documentation Correctness

These items should be done before code hardening so future work starts from an
accurate baseline.

- Update README status language from "release candidate" to the actual 0.1
  line status.
- Fix license wording in README so it matches workspace metadata:
  `MIT OR Apache-2.0`.
- Reconcile `docs/dev/roadmap.md` and `docs/dev/development-plan.md` with the
  post-0.1.0 state.
- Update `docs/dev/design/forwarding-tunnels.md` so StreamLocal is documented
  as implemented, with Unix/platform limits and remaining test gaps.
- Update `docs/dev/design/channels-shells.md` so `ShellAsyncIo` is documented
  as implemented while split read/write halves remain deferred.
- Keep `CHANGELOG.md` ready for `0.1.1` entries as fixes land.
- Add an audit note under `docs/dev/audits/` before publishing.

Acceptance:

- Public docs no longer imply that 0.1.0 is still only a release candidate.
- Implemented features are not described as deferred.
- Deferred features are clearly listed as future work rather than current
  behavior.

## Priority 1: StreamLocal and Tunnel Lifecycle Hardening

StreamLocal forwarding is implemented, but the roadmap still tracks additional
runtime coverage as a hardening target. `0.1.1` should close that gap.

Work items:

- Add Unix-only loopback integration tests for `ForwardSpec::local_streamlocal`.
- Add Unix-only loopback integration tests for `Session::direct_streamlocal()`.
- Add remote StreamLocal forwarding tests if the current `russh` server hooks
  support a reliable local fixture path.
- Test `Tunnel::close()` for StreamLocal cleanup, including socket path cleanup
  where the implementation owns the listener path.
- Test `Tunnel::abort()` on local and remote forwarding paths for no panic and
  no stale forwarding registry entry.
- Add cancellation/race coverage for remote TCP forwarding close while
  forwarded connections are active.
- Confirm that per-connection stream copy failures are logged and do not poison
  the parent tunnel.

Acceptance:

- StreamLocal success paths are covered on Unix.
- Unsupported non-Unix behavior remains typed and documented.
- Remote forwarding registry cleanup is tested for normal close and abort.
- Existing TCP forwarding tests continue to pass.

## Priority 1: Known-Hosts Edge-Case Hardening

`0.1.1` should harden the implemented known-hosts behavior. It should not add
hashed hostname matching or wildcard matching unless a separate accepted design
explicitly moves that work into this patch release.

Work items:

- Add or review tests for malformed lines mixed with valid entries.
- Add regression tests that hashed entries are skipped with warnings and are
  never trusted silently.
- Add regression tests that wildcard-looking entries do not accidentally match
  unrelated hosts.
- Expand save/load tests around non-default ports, revoked entries, comments,
  and source path tracking.
- Review `KnownHosts::set_hash_hostnames()` documentation so it does not imply
  hashing is active.
- Confirm Unix permission failures return `Error::InvalidConfig` without
  exposing sensitive paths beyond necessary diagnostics.

Acceptance:

- Strict unknown-host rejection remains the default.
- Changed and revoked host keys still fail loudly.
- Unsupported hashed and wildcard behavior is documented and covered by tests.

## Priority 1: SFTP Server Error Mapping

The server runtime currently has a local TODO to map handler errors to more
specific SFTP status codes. This is a good patch release hardening item because
it improves interoperability without expanding the public API.

Work items:

- Audit `crates/russh-extra/src/sftp/server.rs` error-to-status mapping.
- Map obvious typed errors to SFTP v3 status codes where doing so is stable:
  unsupported operation, permission denied, bad message/protocol failure, and
  generic failure.
- Keep unknown or ambiguous errors mapped to `SSH_FX_FAILURE`.
- Add server-side integration tests that handler failures encode the expected
  `SSH_FXP_STATUS` response.
- Keep error messages diagnostic but free of secrets and local private data.

Acceptance:

- SFTP handler errors produce stable status codes for common categories.
- Client-side SFTP tests still receive `Error::Sftp` with the expected kind.

## Priority 2: Examples and API Smoke Coverage

Examples are part of the public contract for a first release line. `0.1.1`
should verify that examples still match the current API.

Work items:

- Run all examples through `cargo check --examples --all-features`.
- Add missing feature notes to example headers where required.
- Prefer environment variables for secrets and endpoints.
- Avoid examples that require `accept_any_host_key()` unless the example is
  explicitly for controlled test behavior.
- Add focused API smoke tests for any public helper added during hardening.

Acceptance:

- Example code compiles with documented feature flags.
- Example text does not imply insecure host-key behavior is normal.

## Priority 2: Release Mechanics

The release process should be repeatable for both publishable crates.

Work items:

- Add `## [0.1.1]` to `CHANGELOG.md` only when the release contents are known.
- Bump the workspace version and path dependency versions together at release
  time.
- Verify `cargo package -p russh-extra-core` before packaging `russh-extra`.
- Verify `cargo package -p russh-extra` after `russh-extra-core 0.1.1` is
  locally packageable or available from the registry path used by Cargo.
- Record an audit note with blocking findings, resolved findings, residual
  risks, and verification commands.

Acceptance:

- Package metadata, README, changelog, and docs all agree on `0.1.1`.
- No publishable package contains local-only paths, stale release-candidate
  language, or undocumented feature claims.

## Out of Scope for 0.1.1

These are valid project goals, but they should remain outside this patch
release unless a security issue forces a narrower fix:

- Hashed known-hosts matching or writing.
- Wildcard known-hosts matching.
- Dynamic SOCKS-style forwarding.
- SFTP v4+ or OpenSSH SFTP extensions.
- New macro crates or command-routing macros.
- A broad `russh` version upgrade without a specific bug, security, or
  compatibility reason.
- MSRV changes.
- Feature flag dependency reshaping.

## Verification Gate

Before publishing, run the release checklist from `docs/dev/release.md` plus
the feature matrix from `docs/dev/testing.md`.

Minimum commands:

```bash
cargo fmt --all --check
cargo check --workspace --all-targets --all-features
cargo clippy --workspace --all-targets --all-features -- -D warnings
cargo test --workspace
cargo test --workspace --all-features
cargo doc --workspace --all-features --no-deps
cargo check -p russh-extra --no-default-features
cargo check -p russh-extra --no-default-features --features client,aws-lc-rs
cargo check -p russh-extra --no-default-features --features server,aws-lc-rs
cargo check -p russh-extra --no-default-features --features known-hosts,aws-lc-rs
cargo check -p russh-extra --no-default-features --features shell,aws-lc-rs
cargo check -p russh-extra --no-default-features --features tunnel,aws-lc-rs
cargo check -p russh-extra --no-default-features --features sftp,aws-lc-rs
cargo check -p russh-extra --no-default-features --features server,sftp,aws-lc-rs
cargo check -p russh-extra --no-default-features --features client,ring
cargo check -p russh-extra --no-default-features --features full
cargo package -p russh-extra-core
cargo package -p russh-extra
```

If local network or registry state blocks package or dependency resolution,
record the exact failure in the audit note and rerun in a clean environment
before publishing.
