## Resolved Issues

### API Completions

- **`CommandExit::Signal` adds `core_dumped: bool` field**:
  The `Signal` variant changed from `Signal(String)` to `Signal(String, bool)`.
  All construction and match sites updated across `client.rs`, `shell.rs`, and
  `server.rs`. The `core_dumped` value is now extracted from `russh`'s
  `ChannelMsg::ExitSignal` and propagated through server-side exit signaling.

- **`ChannelKind` adds `X11` and `AuthAgent` variants**:
  New variants for X11 forwarding and agent forwarding channels. Both the
  `ChannelKind` enum and `X11`/`AuthAgent` are `#[non_exhaustive]` so adding
  variants is backward-compatible.

- **`TcpEndpoint` and `StreamLocalSpec` implement `Display` and `FromStr`**:
  `TcpEndpoint::Display` uses bracket notation for IPv6 addresses.
  `TcpEndpoint::FromStr` parses both `host:port` and `[host]:port` formats.
  `StreamLocalSpec::Display` delegates to `Path::display()`.
  `StreamLocalSpec::FromStr` parses any string into a `PathBuf`.
  `StreamLocalSpec::new()` and `From<PathBuf>` now expand tilde.

- **`Pty::with_term()` setter**:
  Builder-style setter for changing the terminal type after construction.

### SFTP Handler Protocol Fix

- **Server-side `readdir` now sends `SSH_FX_EOF` correctly**:
  The `SftpServerHandler::readdir` contract was ambiguous: returning entries
  without a way to signal end-of-directory. The `InMemorySftpHandler` used in
  integration tests was never stateful, returning all entries on every call,
  causing the client-side `readdir` loop to never terminate. Fixed by adding a
  per-handle cursor that advances on each call, returning one entry per call
  and an empty `Vec` when exhausted.

- **Previously-ignored `sftp_server_readdir_and_fstat` test is now active**:
  The `#[ignore]` annotation was removed and the test passes.

### SftpServerHandler Method Coverage

- **Added implementations for `setstat`, `fsetstat`, `realpath`, `symlink`,
  `readlink`** in the integration test `InMemorySftpHandler`. Added corresponding
  integration tests. All 19 `SftpServerHandler` trait methods now have handler
  implementations or tested default behavior in the integration test suite.

### Test Hardening

- **Large data tests**: 1 MiB command output (streaming), 256 KiB tunnel
  bidirectional transfer, 32 KiB SFTP read (exact buffer boundary), 64 KiB
  SFTP read (across buffer boundary in two chunks).

- **ShellAsyncIo lifecycle tests**: drop-without-close does not hang,
  `close()` then drop does not panic, stderr forwarding verified through
  streaming exec.

- **SftpMetadata builder tests**: `with_size`, `with_permissions`,
  `with_uid_gid`, `with_accessed`, `with_modified` round-trip verification.

- **API unit tests**: `Pty::with_term`, `ChannelKind` X11/AuthAgent,
  `CommandExit::Signal` core_dumped, `TcpEndpoint/StreamLocalSpec`
  Display/FromStr/tilde expansion (21 new tests).

## Remaining Risks

- SFTP v4+ protocol extensions and OpenSSH SFTP extensions remain deferred.
- Hashed known-hosts matching/writing, wildcard matching, and `@cert-authority`
  validation remain deferred.
- Dynamic SOCKS-style forwarding remains deferred.
- StreamLocal forwarding tests are Unix-only and do not run on Windows CI.
- Keepalive runtime implementation remains deferred (configuration exists).
- Tracing instrumentation coverage is uneven across modules.
- Split read/write halves for shell/tunnel channels remain deferred.
