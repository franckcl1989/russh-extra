# Audit: 0.1.4 Hardening Release (Final 0.1.x)

Date: 2026-05-17
Auditor: AI independent audit pass
Trigger: release checklist for 0.1.4 + pre-release cross-reference audit

## Scope

Hardening release and final version in the `0.1.x` series. This release fixes
the Windows CI regression, wires silently-ignored timeout configuration, improves
SFTP error quality, fixes base64 data integrity, adds `#[non_exhaustive]` to
seven types, corrects `SftpErrorKind` usage, deduplicates shared code, fills
documentation and observability gaps, and brings the repository documentation
fully in line with the implementation.

## Resolved Issues

### CI Fix

- Windows test failure (`identity_key_file_expands_tilde`) fixed by adding
  `USERPROFILE` fallback to tilde expansion in `auth.rs`, `forward.rs`, and
  `client.rs`, matching the pattern already used in `known_hosts.rs`.

### Bug Fixes

- `DirectTcpBuilder::open()` and `DirectStreamLocalBuilder::open()` now apply
  the configured `channel_open` timeout via `tokio::time::timeout()`.
- `known_hosts.rs` `base64_encode()` no longer silently swallows write errors
  or non-UTF-8 output.
- SFTP read task abort now drains pending requests with a specific error
  message instead of dropping oneshot senders (which caused hangs).
- SFTP write task error is now propagated to callers rather than being replaced
  with the generic `"SFTP channel closed"`.
- `send_and_await` now returns the specific abort reason when a oneshot sender
  is dropped, rather than the misleading `"SFTP request cancelled"`.
- Tunnel bind address parser `expect` message fixed (`{port}` → actual port).

### Code Cleanup

- `SftpResponse::Version` dead variant removed.
- `Error::forwarding_with_source()` constructor added.
- `ServerHostKeySource::Debug` format string fixed (missing closing paren).
- `map_channel_open_error` deduplicated (shell.rs → client.rs).

### Error Kind Correction

- `SftpErrorKind::UnsupportedVersion` changed to `SftpErrorKind::Unsupported`
  in all 17 `SftpServerHandler` trait method defaults. `UnsupportedVersion` is
  retained for actual version mismatch errors (server status mapping, client
  version check).

### `#[non_exhaustive]` Coverage

Added to 7 public types missing it:
`KnownHostsParseWarning`, `SftpDirEntry`, `X11Params`, `AuthDecision`,
`PtyParams`, `ExecResponse`, `RemoteCommand`.

### Tracing

Added `#[tracing::instrument]` spans to: `KnownHosts::check()`, `add_entry()`,
`save()`, `load()`, `Shell::open()`, `Subsystem::open()`, `SftpClient::open()`.

### Tests

21 new unit tests for `SftpOpenMode`, `SftpDirEntry`, and `SftpMetadata` in
`sftp/types.rs`. 2 new unit tests for `SftpClientRuntime` abort reason wiring
in `sftp/client.rs`. Total: 284 tests, 0 failures.

## Remaining Risks

- SFTP v4+ protocol extensions and OpenSSH SFTP extensions remain deferred.
- Hashed known-hosts matching/writing, wildcard matching, and `@cert-authority`
  validation remain deferred.
- Dynamic SOCKS-style forwarding remains deferred.
- StreamLocal forwarding tests are Unix-only and do not run on Windows CI.
- Split read/write halves for shell/tunnel channels remain deferred.
- `SftpFile`, `SftpDir`, and `Tunnel` use `tokio::spawn` in `Drop` for
  best-effort remote cleanup; this may not execute during runtime shutdown.
  Documentation added; architectural fix deferred to 0.2.x.
- `expand_tilde` / `expand_tilde_path` duplicated across 4 production files;
  deduplication deferred to 0.2.x.
- Lock poisoning panics in `KnownHosts` and server internals; mitigation
  deferred to 0.2.x.
- Server `auth_publickey_offered` unconditionally accepts all usernames,
  enabling username enumeration; documented as a known tradeoff.
