## Resolved Issues

- **Documentation governance drift** (Priority 0 from 0.1.1 plan):
  `docs/dev/design/README.md`, `docs/dev/roadmap.md`, `docs/dev/development-plan.md`,
  and `AGENTS.md` status labels reconciled with post-0.1.0 implementation state.
  All top-level sections now carry accurate `Implemented` or
  `Implemented (first runtime slice)` labels.

- **SFTP server error-to-status-code mapping** (Priority 1 from 0.1.1 plan):
  `sftp_error_status()` in `crates/russh-extra/src/sftp/server.rs:547` maps
  typed `SftpErrorKind` variants to SFTP v3 status codes. Added
  `SftpErrorKind::NoSuchFile` and `SftpErrorKind::PermissionDenied` variants.
  Client-side `check_status()` and `expect_handle()` now use `sftp_error_kind_for_code()`
  for consistent status-to-kind mapping.

- **StreamLocal lifecycle hardening** (Priority 1 from 0.1.1 plan):
  `run_local_streamlocal_accept_loop()` now removes the Unix-domain socket file
  after listener shutdown. Added integration tests for StreamLocal tunnel close
  (socket cleanup verification) and abort (no-panic verification).

- **Known-hosts edge-case tests** (Priority 1 from 0.1.1 plan):
  Added 4 unit tests covering wildcard-looking entries not matching unrelated hosts,
  hashed entries skipped with warnings and never trusted, malformed lines mixed with
  valid entries, and `set_hash_hostnames()` documentation behavior.

- **Version bumped** from 0.1.0 to 0.1.1 in root `Cargo.toml` workspace metadata
  and workspace dependency declarations.

## Remaining Risks

- StreamLocal forwarding tests are Unix-only and do not run on Windows CI.
- Hashed known-hosts matching/writing, wildcard matching, and `@cert-authority`
  validation remain deferred.
- Dynamic SOCKS-style forwarding and SFTP v4+ extensions remain deferred.
- Package verification for `russh-extra` depends on `russh-extra-core 0.1.1`
  being available from crates.io first (same publish-order constraint as 0.1.0).
