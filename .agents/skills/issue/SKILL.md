# Drafting Issues

An issue should state:

- the SSH workflow or bug
- the expected behavior
- the observed behavior or missing API
- whether this needs a design doc
- which area labels apply
- the mapping to official `russh` concepts
- the tests needed to prove the behavior

For feature requests, explain how the request relates to `russh` concepts and
do not propose another SSH protocol crate as the solution.
