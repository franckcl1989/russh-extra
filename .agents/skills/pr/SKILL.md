# Drafting Pull Requests

PR descriptions should include:

- Summary of what changed and why.
- Whether this is a small change, an implementation of an accepted design, or a
  roadmap/design-only PR.
- Tests run.
- Links to design docs for public API changes.
- The roadmap entry and design status.
- Feature-gating checks when features changed.

Mention any `russh` API limitations discovered during the work.
